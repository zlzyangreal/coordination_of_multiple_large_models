# 第三方 DSH 插件集成指南

本文面向为 v3.0.0 DSH 原生插件增加下一项扩展声明的维护者。本文定义互操作契约；第三方插件仍是 DSH Profile 中独立管理的 Bundle。

## 1. 通用集成链路

所有第三方插件必须走同一条链路：

`声明 → 发现 → 禁用安装 → 验证身份与能力 → 用户单独激活 → 通过公开接口使用`

1. 维护者在插件配置的 `extensions[]` 中增加声明；未声明项不展示、不安装。
2. 系统调用宿主 `listBundles()`，按声明的 `id` 发现当前 Profile 中的 Bundle。
3. 用户确认安装后，系统调用 `installBundle(spec, { enabled: false, requestId })`。
4. 安装完成后系统重新发现，并核对宿主报告的身份及声明的公开能力探测。
5. 只有门槛通过且用户再次确认，系统才调用 `setBundleEnabled(id, true)`。
6. 实际使用只能走 DSH 或第三方公开、获授权且可验证的接口。

编排、路由、治理和界面不得按插件名称写分支。新增扩展只增加声明，不增加专属安装器、更新器或核心业务模块。

## 2. 声明字段

声明位于本插件配置的 `extensions[]`，只有项目维护者可以新增或修改。系统只解析、展示、校验和执行声明，绝不从名称、用途或模型类型推断依赖等级。

- `id`：宿主 Bundle 的稳定标识，也是发现和启用时的唯一匹配键；必须唯一。
- `policy`：依赖策略，取值为 `optional` 或 `required`；运行时不得自行升级等级。
- `installByDefault`：是否进入默认安装选择；可选扩展应为 `false`。
- `source`：维护者确认的可信安装来源，作为 `installBundle` 的 `spec`；不得按裸包名猜测。
- `displayName`：面向用户的展示名称，不参与身份或能力判定。
- `summary`：用途和范围的简述；未经验证的能力必须明确标为待验证。
- `permissions`：安装及后续使用可能涉及的权限，用于操作前访问告知。
- `documentation`：维护者确认的公开文档或详情链接。
- `probe`：公开能力探测声明；当前受支持的启用门槛是 `{ "kind": "bundle" }`。

声明元数据不是能力证明，也不授予安装、启用、调用、联网或数据外传权限。当前人类安装路由只接受已声明为 `optional`、且具有 `source` 的项目。

## 3. 状态语义

扩展状态统一为七种：

- `not_installed`：`listBundles()` 中没有匹配 `id` 的 Bundle。
- `installing`：用户已授权，该项安装尚未结束；这是操作期状态。
- `installed_disabled`：Bundle 已存在但未启用；不代表适配验证通过。
- `enabled`：宿主报告 Bundle 已启用；是否可用仍受公开能力契约约束。
- `incompatible`：宿主在 Bundle 条目中报告错误；隔离该项并展示原因。
- `failed`：安装失败，或宿主报告已安装包缺失等不可用情况。
- `unknown`：插件管理器不可用或 `listBundles()` 失败，无法取得可靠 Bundle 清单。

必须始终区分：`已安装 ≠ 已启用 ≠ 已验证`。
文件存在、缓存命中或 Bundle 名称出现都只是“存在性”，不是激活资格。
当前门槛要求宿主报告具体版本身份，并且声明含可用的公开 `bundle` 探测。任一条件缺失时拒绝由本插件激活，并引导用户在 DSH 插件管理中处理。

## 4. 宿主互操作要求

目标 DSH 宿主必须公开以下能力；本集成不假设其他宿主 API：

- `listBundles()`：发现当前 Profile 的 Bundle、版本、启用状态及错误信息。
- `installBundle(spec, { enabled: false, requestId })`：独立安装和注册，完成后保持禁用。
- `setBundleEnabled(id, enabled)`：在用户单独确认后切换 Bundle 启用状态。
- `cancelInstall(requestId)`：停止对应安装请求，用于取消或安全停止。

不得把普通包依赖、磁盘目录或私有配置记录伪装成已注册、已启用或已验证。
仅“能列出”不够：存在性不能证明版本身份、接口兼容性或能力可调用。
当前 `/_multimodel/*` 安装和激活路由是人类专用控制面，要求同源、CSRF 和显式确认。这些路由不是模型工具，常规任务、日志、探测和总开关均不得隐式触发安装或激活。

## 5. 故障与生命周期隔离

批量安装按声明顺序逐项执行并逐项返回结果；单项安装就是一项批次。
一个扩展失败不得回滚其他已经成功的扩展，也不得阻断主插件的基本能力。
受影响项的 Profile 文件恢复由宿主安装机制负责，本插件不接管宿主事务。
失败项只记录阶段、原因和下一步；不得假报成功或扩大到无关 Bundle。

本插件不得强制覆盖、升级、降级、移除或重新启用独立 Bundle。
不得读取或写入第三方私有配置、账号、密钥、数据库、缓存或固定目录。卸载本插件不默认卸载第三方插件；移除第三方 Bundle 必须另行明确授权。

## 6. 上游更新

第三方源码、发布、配置、更新、回退和卸载始终归 DSH 或第三方上游所有。上游变化后，本插件只通过 `listBundles()` 和声明的公开探测重新发现、重新判断。
兼容则继续使用公开能力；不兼容则隔离该项、记录原因并提示用户处理。
其他扩展和本插件已有的独立接入能力不应被连带回滚或停用。

不得 vendor、复制、内嵌、fork 后魔改或 patch 上游插件。不得维护第三方固定模型表、内部路径快照、版本白名单或专属更新器。正常任务、日志、兼容检查和总开关不得自动安装、升级、降级或移除插件。

## 7. 数据、权限与治理

安装确认必须展示目标 Profile、来源、用途、声明权限和可能访问的数据类型。实际能力调用前还应说明发送哪些内容、发送到哪里，以及可能产生的费用。不得外传密钥、私有配置、未授权提示词、文件内容或其他敏感数据。

安装授权只覆盖本次安装，不等于启用授权；启用也不等于使用授权。
安装或启用不自动批准模型调用、数据外传、额度消耗或高风险权限。
实际使用继续遵守 L1/L2/L3：插件/模型加入及不可分类事项归 L1，
方向、接口、权限、成本等实质变化归 L2，已授权范围内的执行归 L3。
团队新增须经用户同意；插件注册等受控操作须通过既有权限守卫。
总开关开启时须先确认四十条规则契约；契约缺失或无效时受控操作失败关闭。

## 8. 维护者接入清单

1. 在 `extensions[]` 增加完整声明，使用唯一 `id`，不要修改核心编排代码。
2. 核对 `source`、`documentation`、`summary` 和 `permissions` 是否可向用户准确展示。
3. 对可选项设置 `policy: "optional"` 与 `installByDefault: false`。
4. 只声明宿主可公开验证的 `probe`；没有公共契约就明确显示不兼容。
5. 验证七种状态、取消、失败隔离、重复发现以及安装后保持禁用。
6. 验证身份未知、探测缺失或不兼容时，系统不会调用启用接口。
7. 用户单独确认激活后再次 `listBundles()`，以宿主状态为准，不猜测成功。

## 9. 示例：假想可选扩展

以下 `dsh-example-search` 仅为声明格式示例，不表示该仓库或来源真实存在：

```json
{
  "id": "dsh-example-search",
  "policy": "optional",
  "installByDefault": false,
  "source": "github:example-org/dsh-example-search",
  "displayName": "示例搜索桥接器",
  "summary": "通过公开 Bundle 契约提供搜索能力；具体能力安装后验证。",
  "permissions": ["plugin:install", "network:access"],
  "documentation": "https://example.invalid/dsh-example-search",
  "probe": { "kind": "bundle" }
}
```

用户可见流程应精确为：

1. 用户打开“可选扩展”，看到用途、来源、权限和“未安装”，默认不勾选。
2. 用户点击“安装”，确认目标 Profile、来源与权限；界面显示“安装中”。
3. 宿主禁用安装；成功后显示“已安装未启用”，不得显示“可用”。
4. 系统重新发现具体版本并检查声明的 Bundle 探测；失败则显示原因并隔离。
5. 门槛通过后，用户另点“启用”并再次确认；宿主启用后重新发现为“已启用”。
6. 首次实际调用仍按数据告知和 L1/L2/L3 取得授权，再通过公开接口使用。

真实的 `dsh-our-free-model` 仍是可选扩展，默认不安装；
本文不声称它已安装、已启用或已验证。

## 10. 边界声明

本指南定义声明、宿主交互、状态、授权和故障传播的互操作边界。
它不是操作系统沙箱、第三方代码审计、供应链认证或 DSH 官方兼容认证。
第三方代码仍在本插件的强制范围之外运行，依赖 DSH 的沙箱、权限与审批机制。
本插件只能约束自身控制的脚本、路由和调用链，不能宣称全局拦截或代理外部插件。
